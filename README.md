# 一人公司 · 案例知识库与内容工厂

> **把验证过的问题解法，交到被问题困住的人手里。**

老总（你）+ AI 员工（采编、提炼师、写手）经营的一人公司。主库在本仓库（Git，Markdown），首发知识星球，长文公众号，后期改编小红书。

## 使命

**把验证过的问题解法，交到被问题困住的人手里。**

产品是解法，顾客是被问题困住的人，承诺是验证过。深层表述：帮普通人完成从「听说过」到「做得到」的转化——读者的困境从来不是信息不够，而是不知道哪个可信、怎么落地、适不适合自己。我们收钱的理由，就是把这三件不确定的事变成确定。

## 愿景

成为中国普通人最信任的生活问题解法库——当一个人被生活问题困住时，先想到的不是搜索引擎，而是「来这里查查，有没有人验证过」。

## 账号定位

- **一句话简介（平台通用）**：只发验证过的生活问题解法｜每个方案都标明：我试过 / 已核实 / 仅引用，并告诉你什么时候别用。
- **定位公式**：对于【滩头顾客：与老总同类的普通人——注重生活决策质量、肯为"少走弯路"付小钱】，我们是【经过验证的生活问题解法库】——每个方案都有证据等级和适用边界；不同于【整理汇编型账号（信息密、但无人验证）】和【焦虑贩卖型账号（先制造问题再卖解法）】。
- **我们是**：问题解决者、方案传播者。
- **我们不是**：热点复读机、万能方法贩子、情绪内容供应商。**解法是产品，陪伴是通道。**

## 招牌

**可信**——「这个人只发验证过的东西」的声誉，由证据等级制度承载。筛选能力和可执行清单是基本盘，不是招牌；只有可信无法被 AI 复制。

## 使命三问（一切选题与活动的裁判）

1. 【解问】它对应一个具体问题吗？动笔前能说出「谁、正被什么困住」吗？
2. 【可信】方案的证据等级是多少？诚实标注了吗？
3. 【可用】拿到手能直接照做吗？适用边界写清楚了吗？

三问全过 → 进选题候选；任何一问含糊 → 回 inbox 继续养，或丢弃。**犹豫不决时，回使命。**

## 反使命（永远说不）

- 不追热点，除非热点背后是真问题
- 不贩卖焦虑（先制造问题再卖解法，是使命的反面）
- 不发布无证据等级的内容
- 不做纯故事纯情绪、没有解法交付的内容
- 不搬运不标注——违背即信誉死亡

## 赚钱观

**付费是体温计，不是方向盘。** 使命决定写什么；付费数据检验选题判断和交付质量。两者冲突时（某篇流量高但违背三问），回使命。第 6 个月付费验证的也是使命假设本身——如果读者不为「验证过的解法」付钱，要修的是使命假设，不是往流量上跑偏。

## 组织架构

| 角色 | 职责 | 拍板点 |
|---|---|---|
| **老总（你）** | 选题、亲身实践、终稿 | ①拍板选题 ②终稿过目 ③一秒选标题 |
| **采编**（.zcode/agents/case-editor.md） | 清 inbox → 案例卡 → 过三问的选题候选 | — |
| **提炼师**（.zcode/agents/distiller.md） | 案例卡 → insights 可复用原则（感性→理性） | — |
| **写手**（.zcode/agents/writer.md） | 案例卡+洞察 → 母本六段成稿 + 3 标题候选 | — |

第二阶段扩编：改编师（平台适配，小红书）、运营（发布/评论/数据，接 zsxq-skill）。

## 节奏与例会

每周日晚（详见 docs/例会流程.md）：

1. 运行 workflow `weekly-review`：清 inbox → 案例卡 → 选题候选
2. **老总拍板选题**
3. 运行 workflow `produce-article`（参数 casePath=选中案例卡）：提炼 → 成稿
4. **老总终稿过目 + 选标题**
5. 手动发布（当前阶段）

每周 1 篇成稿，不日更。

## 文风与模板

混合体六段式（templates/母本模板.md）：场景 → 故事 → 方案清单 → 结果与代价 → 适用边界 → 证据标签+引用。小红书取「场景/方案/边界」三段。案例卡见 templates/案例卡模板.md，洞察见 templates/洞察模板.md。

## 证据等级

| 标签 | 含义 |
|---|---|
| [亲历验证] | 我自己试过，结果如实写 |
| [他人案例·已核实] | 找到可追溯的原始出处 |
| [他人案例·仅引用] | 仅有转述来源，未核实；日后亲身实践可升级重发 |

引用最低标准：**渠道 + 日期 + 可识别来源**，低于标准不发布。详见 CONTEXT.md 与 ADR-0001。

## 案例生命周期

`素材 → 已提炼 → 【已实践 或 已核实】→ 可发布 → 已发布 → 反馈回流`

## 工具路线

1. **现在（手动发布）**：母本 md → [doocs/md](https://github.com/doocs/md) 渲染 → 粘贴知识星球（首发）与公众号
2. **第二阶段**：[zsxq-skill](https://github.com/unnoo/zsxq-skill) 自动发星球与回评、cose 多平台同步、改编师 Agent 上小红书
3. **第三阶段**：[xhs](https://github.com/ReaJason/xhs) 自动化小红书

输入侧：[ZsxqCrawler](https://github.com/2977094657/ZsxqCrawler) / [zsxq-spider](https://github.com/PlexPt/zsxq-spider) 采集星球精华进 inbox（仅作私人素材库，发布必须按引用标准标注）。
